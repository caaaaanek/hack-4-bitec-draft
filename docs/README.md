# docs — джерела хакатону і документація проєкту

```
docs/
├── raw/        оригінали (HTML, PDF) без змін + SOURCES.md (URL, дата, SHA-256)
├── md/         оброблені версії: Markdown (+ .txt), картинки в <doc>-img/
├── tools/      скрипти конвертації (html2md, pdf2md, check_words, fixes/)
├── api/        openapi.json — контракт API бекенду, frontend-mapping.md — відповідність екранів маршрутам
├── contracts/  контракти інтеграцій: Mitra (тема 2), модуль «Перевірки»; схеми й приклади
├── img/        скриншоти головних екранів для README
├── backend.md  архітектура, ролі, модель даних, API
├── features.md адвокат диявола, агент-черговий, нормативка, автопілот хвилі, флешкартки (API для фронтенду)
├── integrity-index.md  методика Integrity Index
├── recommendations.md  рекомендації, рішення й заходи з прогону (генерується: backend/scripts/gen_docs.py)
├── cross-check.md      зіставлення РГ / ОС / експертів і фактів з прогону (генерується тим самим скриптом)
├── integration-map.md  карта інтеграції: модуль у наявній ІС, джерела фактів, вихідні потоки, API (результат 9)
├── ecosystem.md        концепція інтеграції з іншими рішеннями у сфері доброчесності (результат 12)
├── anonymity.md        захист анонімності, модель загроз, залишкові ризики (результат 6)
├── abuse-analysis.md   можливі зловживання й запобіжники (результат 10)
├── demo-scenario.md    демонстраційний сценарій для відео й перевірки (результат 2)
├── dashboard.md        Dashboard керівника: блоки, числа демо, деталізація (результат 4)
├── time-savings.md     розрахунок економії часу порівняно з ручним порядком (результат 8)
├── ai.md               як ми використали ШІ (результат 11)
├── role-workflows.md   покроковий workflow кожної ролі в повній хвилі
├── frontend-backlog.md що бекенд уже вміє, а екрана ще немає
├── analysis-20-11.md   звірка з вимогами станом на 20.11
└── run.md      як запустити (Docker, розробка, демо-дані)
```

Що тут лежить:

| PDF завдання 3 | `md/zavdannia-3-1811daff.md` | Те саме, PDF-версія |
| Рекомендації НУОУ (99 с.) | `md/recommendations_transform_dobrochesnist.md` | Дод. Б — чек-лист, Дод. В — анкети 1 і 2, Дод. Г — шаблон звіту, Дод. Д — план заходів |

Як додавати й обробляти нові документи — у скілі
[`.claude/skills/ingest-docs/SKILL.md`](../.claude/skills/ingest-docs/SKILL.md).
Коротко: оригінал → `raw/` (+ рядок у `raw/SOURCES.md`), конвертація скриптами з `tools/` → `md/`,
перевірка повноти `tools/check_words.py`. `raw/` ніколи не редагувати руками; `md/` перегенеровується з `raw/`.
