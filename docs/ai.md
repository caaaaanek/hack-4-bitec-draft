# Як ми використали ШІ (Політика ШІ, п. 5)

## Інструменти й навіщо

| Інструмент | Де | Навіщо |
|---|---|---|
| Claude (Anthropic, США), Claude Code | розробка | Чернетки коду бекенду й фронтенду, тестів, документації; конвертація джерел хакатону в Markdown (скіл `.claude/skills/ingest-docs`); аудит безпеки й анонімності |
| Codex, Cursor | розробка | Допомога в редакторі (правила для агентів — `AGENTS.md`) |
| Gemma (`gemma4-26b`, Google, відкрита модель) на шлюзі кафедри або власній Ollama | **у продукті, опційно** | Асистент лише пояснює вже пораховані правилами числа й допомагає формулювати текст звіту; може перефразувати питання «Адвоката диявола» (числа звіряються з оригіналом); вимкнений за замовчуванням |

Не використовували: моделі й сервіси з РФ, РБ, КНР (бекенд відхиляє `deepseek`, `qwen`, `glm`, `kimi`, `yandex`, `gigachat`
та адреси `.ru`, `.by` — `FORBIDDEN_MARKERS`), а також будь-які зовнішні сервіси без явного дозволу (`LLM_ALLOW_EXTERNAL`).
Дані — лише синтетичні.

## Що вирішила команда (а не модель)

- **Користувач і проблема:** керівник ВВНЗ і робоча група, яким потрібна чесна картина системи доброчесності без паперового
  зведення; учасник, який відповість щиро лише тоді, коли певен в анонімності.
- **Принципи продукту:** оцінюємо систему, а не людей; підрозділ порівнюємо лише із собою, рейтингу немає; кожне число має
  правило; ядро працює без ШІ; ШІ пояснює, людина вирішує; лише агрегати груп ≥ k.
- **Чого продукт свідомо не робить:** не оцінює окремих посадових осіб; не показує, хто що відповів, і поіменних списків
  «хто не пройшов»; не тягне поіменних декларацій (лише агрегат «X з Y»); не дає моделі ставити оцінки, рівні чи статуси.
- **Ключові рішення:** модель зрілості НАЗК (Культура / Система / Підзвітність, 5 рівнів) замість зон за TI GDI з першого
  концепту; правило реальності «самооцінка не вища за факти + 1 рівень»; ваги джерел 0,35 / 0,25 / 0,20 / 0,20; трекер заходів
  у нашій системі, а тема 2 — додаткова інтеграція; одноразові посилання для особового складу.

## Що розглянули й відкинули

- «Адвокат диявола» й аналіз нормативки на моделі (генерація питань, RAG з ембедингами) — замінили явними правилами й локальним TF-IDF: той самий вхід дає той самий результат, працює в закритому контурі; модель лише опційно перефразовує питання.
- Автопілот, що сам приймає рекомендації — відкинули: рішення ухвалює посадова особа.

- «Знайди ще»: пошук заходів моделлю в інтернеті — відкинули для ядра (закритий контур, неперевірені джерела); лишили
  курований каталог Додатку Д.
- Поіменний контроль декларацій і список «хто ще не пройшов» — суперечать принципу «не оцінювати людей».
- Брати код проєктів інших команд (ARTEMIDA, Iudicium) — лише інтеграція через API чи мок.
- Довіряти моделі розрахунок індексу чи рекомендацій — замість цього детерміновані правила (`services/scoring.py`,
  `services/recommendations.py`), які дають той самий результат на тих самих даних.

## Як перевірити, що висновки дають правила

`GET /api/v1/methodology` — усі ваги й пороги; поле `rule` у кожному числі результатів і в кожній рекомендації;
тест `test_results.py::test_same_input_gives_same_snapshot`; асистент вимкнений за замовчуванням, і вся система працює без нього.

посилання чи фото.
