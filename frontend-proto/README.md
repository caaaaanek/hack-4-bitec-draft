# frontend-proto

Фронтенд Integra на React (Vite), власний дизайн. Методика, дані й тексти взято з першого прототипу команди (Integrity Index, 8 ролей, 5 правил рекомендацій), а його заглушки тут замінено робочими екранами: звіт, керування циклом, анкети, чек-лист «чотири ока», журнал з ланцюгом хешів, порівняння.

Демо: https://integrity-prototype.vercel.app

## Запуск

З бекендом (основний режим): `docker compose up --build` у корені репозиторію → http://localhost:8080, вхід демо-логінами
(див. `docs/run.md`). Режим визначається автоматично: відповідає `GET /api/v1/config` — дані й вхід з бекенду (`src/lib/api.js`).

Розробка:

```bash
npm install
npm run dev                     # http://localhost:5173; /api і /health → BACKEND_URL (за замовчуванням http://127.0.0.1:8000), без бекенду — демо-дані
npm run build                   # збірка в dist/
./start.sh                      # збірка + асистент на локальній моделі Ollama (gemma3:4b) → http://127.0.0.1:3000
```

Кнопка «Відкрити в Mitra» у картці заходу веде на `VITE_MITRA_URL` (задається під час збирання), за замовчуванням
https://mitra.csit-mitit.com. Захід, уже пов'язаний у Mitra, відкривається за власним посиланням з бекенду.

## Екрани для модулів автоматизації

Працюють з бекендом; без нього «Навчання» має демо-колоди, «Питання перевірки» і сигнали в дзвіночку показують приклад із `docs/features.md`, решта пише «Доступно в режимі з сервером».

| Модуль | Де в інтерфейсі | Файл | Ролі |
|---|---|---|---|
| Питання перевірки | кнопка «Підготуватися до перевірки» на «Огляді» і у «Звіті» (бічна панель), повний екран «Питання перевірки»; кожне питання має «До числа» | `views/Insights.jsx` | admin, commissioner, leader, auditor |
| Сигнали | у дзвіночку в шапці («Потребує дії», лише критичні й попередження, клік веде туди, де виправляють) і до трьох пунктів у «Що потребує уваги» на «Огляді»; окремої вкладки немає | `views/Insights.jsx`, `components/NotesPop.jsx` | leader, observer, auditor, admin |
| Навчання (флешкартки) | пункт меню «Навчання» (стос карток із перегортанням), картка «Навчання» в «Мої результати» | `views/Learn.jsx` | усі; охоплення: admin, coordinator, commissioner, leader, auditor |
| Автопілот хвилі | розділ вибраної хвилі в «Керуванні циклом» (уповноважений, `#autopilot` веде туди) | `views/Autopilot.jsx` | admin |
| Що змінилось | пункт меню «Що змінилось», екран «Що змінилось для нас» | `views/Normative.jsx` | admin, coordinator, commissioner, leader, auditor |
| Перевірки | пункт меню «Перевірки» | `views/Checks.jsx` | admin |
| Сповіщення | дзвіночок у шапці | `components/NotesPop.jsx` | усі після входу |

Нові екрани мають той самий каркас, що й «Огляд»: ряд KPI-плиток, заголовки секцій з іконкою в тонованому колі (`components/modkit.jsx`), довгі пояснення під «Докладніше».

Назва продукту: **Integra** (слово-знак, заголовок вкладки, імена файлів експорту `integra-…`). Назва показника «Індекс доброчесності» (Integrity Index) не змінюється.

Якщо `GET /api/v1/config` не відповідає (мережа, збій 5xx), показується «Сервер недоступний» з кнопками «Повторити» й «Відкрити демо-режим». Відповідь 404 або сторінка замість JSON (Vercel без бекенду) відкриває демо одразу. Тому `npm run dev` без бекенду спершу покаже цей екран.

## Структура

- `src/` — React-код: `lib/` (модель, стан, API, роутер), `components/`, `views/` (екрани), `ai/` (асистент), `styles/`. Детально — `CLAUDE.md`.
- `api/assistant.js` — серверна функція асистента (будь-який OpenAI-сумісний `/chat/completions`, ключ лише в змінних оточення).
- `server.mjs`, `start.sh` — локальний сервер для закритого контуру: віддає `dist/` і `/api/assistant`.

ШІ лише пояснює вже розраховані правилами числа й пише чернетки; вимикається перемикачем, без нього все працює.
